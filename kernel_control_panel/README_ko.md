# SampleKernel1 Kernel Studio 사용 안내

로드된 SampleKernel1 드라이버로 프로세스·메모리·검색·모듈·스레드·중단점·DLL 작업을 수행하는 로컬 컨트롤패널입니다. 기존 도구와 DLL·이미지 함수 작업 공간을 15개 화면으로 제공합니다. 드라이버 2.2부터 함수 생성·조회·참조 해제 IOCTL 3개를 포함하며 전체 ABI는 37개, 활성 지원 기능은 34개입니다. 2.3 수정본은 이 ABI를 유지하면서 대량 결과 생성·해제의 경계를 일치시킵니다. 비활성 호환 기능은 제외하며, 반환 목록 해제는 자동 처리합니다.

## 시작

1. 현재 콜백이 제거된 드라이버를 로드합니다. 이미 로드했다면 그대로 사용합니다.
2. 이 폴더에서 `python server.py`를 실행합니다. 필요한 패키지는 `requirements.txt`에 있습니다.
3. <http://127.0.0.1:8000/>를 엽니다. 이전 화면이 남아 있으면 새로 고칩니다.
4. **대상 프로세스 선택**을 열면 실행 중인 프로세스 목록을 자동으로 커널 조회합니다. 이름/PID로 검색하고 **선택**을 누르거나, PID를 직접 입력해 **대상 확인 / 선택**을 누릅니다. **목록 새로 고침**으로 변경 사항을 조회할 수 있습니다. 선택 직전에 종료 상태와 생성 시점을 다시 확인합니다. 대상이 바뀌면 이전 주소와 입력 양식은 초기화됩니다. 페이지를 다시 열면 종료된 프로세스의 PID를 자동 재사용하지 않도록 대상을 새로 선택합니다. 북마크는 유지됩니다.

외부 CDN 없이 로컬 파일을 사용합니다. 서버는 127.0.0.1에만 연결합니다. 변경 작업은 실행 버튼으로 요청하며, 화면의 새로 고침은 메모리 쓰기나 스레드 변경을 반복 실행하지 않습니다.

프로세스 확인·메모리 맵·New/Next 스캔·반환 버퍼 복사/해제는 모두 커널 IOCTL을 사용합니다. 대상 프로세스의 `OpenProcess`·`ReadProcessMemory`·`VirtualQueryEx` 경로와 psutil 열거를 사용하지 않습니다. 현재 드라이버에 시스템 전체 PID 열거 IOCTL이 없으므로 기존 `QUERY_PROCESS_EXTENDED (0x81A)` 요청으로 기본 PID 4~65,536 범위를 탐색합니다. 선택 창에서 262,144 또는 1,048,576까지 확장할 수 있고, 범위 밖 PID는 직접 입력할 수 있습니다. 이 드라이버의 CID 조회가 하위 두 비트를 동일 대상으로 처리하므로 중복을 피하도록 4 단위의 정규 PID를 조회합니다. 종료된 프로세스와 조회 불가 프로세스는 제외되므로 시스템 전체 목록의 완전성을 보장하는 열거는 아닙니다. 새로 열린 창과 새로 고침은 새 조회를 요청하며, 동시 요청은 합치고 일반 API 조회의 캐시는 최대 3초입니다. 사용자 프로세스 핸들 대신 드라이버 장치 연결에 필요한 `CreateFileW`·`DeviceIoControl`·`CloseHandle`만 사용합니다. New/Next의 숫자 비교·후보 필터링과 PE 해석은 커널이 반환한 바이트를 대상으로 유저모드에서 계산합니다.

## 작업 흐름

- **메모리 편집 / 관리**: 읽기·형식별 쓰기·바이너리 덤프·할당·해제·보호 변경·프로세스 간 복사·패턴 채우기.
- **값 / 패턴 / 문자열**: 커널 값 검색·AOB 및 영역 검색·다단계 검색·문자열 추출·포인터 참조 검색. 검색 결과의 Hex / Watch / 분석 버튼으로 다음 도구에 주소를 전달합니다.
- **Watch / 값 고정**: 주소 등록·편집·목록·삭제·고정. 고정 시작 시 실제 메모리에서 값을 읽습니다. float / 64비트 값의 정확도를 유지하며, 읽기·쓰기 실패나 프로세스 종료·교체를 감지하면 고정을 해제합니다.
- **메모리 / 이미지 덤프**: 최대 16GiB 범위 덤프·이미지 하나·모든 MEM_IMAGE·진행률·취소·이어쓰기·바이너리/ZIP 다운로드.
- **모듈 / PE / 주소**: 커널 메모리 맵·모듈·PE 헤더와 섹션·가져오기/IAT·내보내기·주소 소속 분석.
- **스레드 / 레지스터**: 목록·상세·컨텍스트·부분 레지스터 변경·중단/재개·우선순위·CPU 마스크·일괄 작업·디버거 숨김. 레지스터 편집은 선택 PID·스레드 생성 시점을 확인하고, 잠시 정지한 상태에서 지정 필드만 변경하여 전체 일반 레지스터를 재조회/검증한 뒤 정지 횟수를 되돌립니다. 검증 불일치는 실패와 실제 관측값을 반환합니다. 편집 요청 중에는 대상 전환을 차단합니다.
- **하드웨어 중단점**: 실행 / 쓰기 / 읽기·쓰기 유형, 1·2·4·8바이트 길이 설정·조회·목록·복원. 제거 실패 시 복구 정보를 보존합니다.
- **스냅샷 / 패치 / 분석**: 원본 저장·차이 비교·복원·패치 원본 확인·복구·포인터 체인·사용자 정의 구조체·필드 쓰기·자동 해석·x86/x64 명령어 분석.
- **작업 큐 / 시나리오**: 검색을 백그라운드에서 실행하고 진행 중 요청 완료 후 취소합니다. JSON 시나리오는 최대 32단계를 순서대로 실행하며 `$이름.필드`로 이전 결과를 참조합니다.
- **호출 이력 / 기능**: 실제 IOCTL 호출 상태와 시간·횟수·지원 기능을 확인합니다.

| 모듈 / 함수 주소 계산 | `kernel32.dll!LoadLibraryW`, `ntdll.dll!#ordinal`, `app.exe+0x1000` 또는 숫자 주소를 입력합니다. |
| 주소 소속 분석 | 주소의 영역·보호·이미지·PE 섹션을 확인합니다. |

| 문자열 조건 검색 | 포함·접두사·정확한 일치 및 대소문자 옵션을 사용합니다. |

| 복구된 패치 기록 삭제 | 복구가 완료된 패치만 삭제합니다. 아직 복구하지 않은 원본은 보존합니다. |

모듈 목록에서 기준 주소를 확인하고 **PE 가져오기 / IAT** 또는 **PE 내보내기**에 입력합니다. 함수 주소 계산 결과와 메모리 분석 결과는 표의 주소 버튼으로 다른 도구에 전달할 수 있습니다. 전달 내보내기는 이미 로드된 모듈을 최대 8단계 추적하며, 로드된 모듈로 확인할 수 없는 API-set 이름은 오류로 표시합니다.

## 대용량 / 이미지 덤프

**메모리 / 이미지 덤프** 화면에서 다음 중 하나를 선택합니다.

- **대용량 범위 덤프**: 시작 주소와 전체 크기를 입력합니다. 최대 16GiB이며 1MiB 한도는 전체 덤프에 적용하지 않습니다.
- **이미지 하나 덤프**: `main`, `Project1.exe`, `KERNELBASE.dll` 또는 `0x...` 이미지 기준 주소를 입력합니다.
- **모든 MEM_IMAGE 덤프**: 커널 맵의 EXE·DLL 이미지를 모두 개별 `.mapped.bin` 파일과 `images.zip`으로 저장합니다.
- **덤프 작업 목록**: 대상 선택 없이 서버 세션의 작업을 조회합니다.

커널 메모리 맵으로 범위를 정하고, 최대 4KiB 단위의 읽기 IOCTL을 순차 요청합니다. 분할 묶음은 4KiB~1MiB로 지정하며 이 간격마다 대상의 시작 키를 재확인합니다. 결과는 서버 디스크에 이어 써서 전체 크기에 비례하는 RAM/JSON/Base64/브라우저 Blob을 만들지 않습니다. 기본 저장 위치는 이 폴더의 `dumps/<덤프 ID>/`이며 `KERNEL_STUDIO_DUMP_DIR`로 바꿀 수 있습니다. 드라이버 반환 버퍼 해제도 커널 IOCTL을 사용합니다. 대상 프로세스 핸들·OpenProcess·ReadProcessMemory·VirtualQueryEx는 사용하지 않습니다.

기본 범위 덤프는 읽기 실패 시 중단합니다. 이미지 덤프는 읽을 수 없는 페이지와 매핑되지 않은 구간을 0으로 채워 RVA를 유지하고, 위치·크기·실패 상태를 `manifest.json`에 기록합니다. **0으로 채운 바이트는 원본 데이터가 아닙니다.** 이미지 크기 정보가 있으면 추가 보호 구간을 제외하고 그 크기로 저장합니다. 크기 정보가 없을 때만 해당 MEM_IMAGE의 매핑 범위를 사용하며 파일 기록의 `size_source`로 구별합니다. 필요하면 이미지 덤프도 중단 정책으로 바꿀 수 있습니다. 커널 응답 크기 오류나 반환 버퍼 해제 실패는 0 채움 정책에서도 즉시 실패합니다.

진행률·완료 바이트·0 채움·커널 읽기 횟수·파일 SHA256을 표시합니다. 취소는 현재 커널 요청 완료 후 적용하며 `.part` 파일을 보관합니다. 같은 서버 세션에서 **이어쓰기**를 누르면 프로세스 시작 키, 부분 파일 길이와 SHA256을 확인한 뒤 마지막 완료 위치부터 재개합니다. 프로세스 종료/교체 시 재개를 거절합니다. 서버 종료도 작업 중단과 반환 버퍼 해제를 기다린 후 장치를 닫습니다. 진행 중인 작업·이어쓰기 상태는 서버 세션에 보관하며 파일과 JSON 기록은 디스크에 남습니다. 완료된 작업의 다운로드 이력은 서버 재시작 후 JSON 기록에서 복구합니다. 작업이 끝난 뒤 **파일·이력 삭제**를 누르면 해당 작업 디렉터리만 삭제합니다. 다운로드 중인 파일은 삭제를 거절합니다.

완료 파일은 일반 다운로드 링크로 전송합니다. HTTP Range 부분 다운로드와 SHA256/ETag 헤더를 지원하므로 같은 파일의 네트워크 이어받기도 가능합니다. 최대 4개 작업을 대기/실행하고 실제 덤프는 한 번에 하나씩 수행합니다. 전체 덤프와 ZIP에 필요한 여유 공간도 확인합니다. 기존 작은 바이너리 덤프 API/화면의 1MiB 입력·출력은 유지합니다.

이미지 파일은 **로드된 메모리 배치**이며 `파일 오프셋 = VA - 이미지 기준 주소`입니다. 디스크 PE의 RawData 배치로 재구성하거나 실행 가능한 EXE를 복원하는 기능은 아닙니다. 대상은 계속 실행하므로 서로 다른 페이지와 취소 전후의 데이터는 한 시점의 원자적 스냅샷이 아닙니다.

API: `POST /api/studio/dumps`에 `{pid, mode: "range"|"image"|"images", address, size, module, policy: "strict"|"zero", chunk_size}`를 전달합니다. 작업 조회는 `GET /api/studio/dumps/{id}`, 취소/재개는 `POST .../{id}/cancel`, `POST .../{id}/resume`, 파일은 `GET .../{id}/files/{name}`입니다.

스레드 목록 IOCTL은 최대 64개입니다. 일반 컨텍스트는 RIP/RSP/RBP, RAX~RDI, R8~R15, EFLAGS의 18개 필드를 제공하며 XMM/YMM·세그먼트 레지스터는 이 ABI에 포함되지 않습니다. TID/PID·TEB·시작 주소·생성 시각·CPU 시간은 조회 정보이고, 우선순위·CPU 마스크와 일반 레지스터는 별도 변경 작업을 사용합니다. 캡처한 레지스터는 해당 조회 시점의 값입니다.

## 저장 범위와 제한

DLL 로드 검증, MEM_IMAGE의 DLL·EXE 함수 목록, Capstone 상세, 선택 PDB 이름·형식 복원, 커널 함수 호출은 **DLL / 이미지 함수** 화면에 있습니다. 함수 호출에는 드라이버 **2.2 이상**이 필요합니다. 단일 64비트 정수/포인터 인자와 32비트 종료값을 지원하며, 실행 중인 호출은 재실행 없이 조회합니다. 자세한 사용 방법과 상한은 [DLL_WORKBENCH.md](DLL_WORKBENCH.md)를 참고하세요.

- 한 번의 읽기·쓰기·비교는 최대 1MB입니다. 큰 읽기는 4KB씩 완료 여부를 확인하고 반환 버퍼를 해제합니다.
- 표 결과는 최대 5,000행입니다. 비교는 모든 바이트의 변경 수를 계산하고 표시 행만 제한합니다.
- 원본 스냅샷은 16개, 메모리 맵은 8개, 패치 이력은 64개, Watch는 256개까지 보관합니다. 서버 종료 시 값 고정을 해제합니다.
- 스냅샷·패치·메모리 맵은 서버 세션에 저장합니다. 북마크는 브라우저에 저장하며 JSON 가져오기가 쓰기나 고정을 자동 실행하지 않습니다.
- 메모리 맵 비교는 두 조회 시점의 차이를 보여 줍니다. 중간에 생겼다가 사라진 변경까지 기록하는 기능은 아닙니다. 여러 요청으로 읽는 데이터는 대상이 동시에 바꾸면 일관된 한 시점의 복사본이 아닐 수 있습니다.
- DLL 요청의 성공 응답만으로 대상 DLL 초기화 완료를 단정하지 않습니다. 로딩이 오래 걸리면 요청 반환 뒤에 완료될 수 있으므로 모듈 목록에서 결과를 확인합니다.
- 문자열 필터는 최대 5,000개 반환 항목과 각 문자열의 최대 4KB 미리보기 범위에 적용합니다. 일반 가져오기 테이블을 해석하며 지연 로딩 가져오기 테이블은 별도 해석하지 않습니다. IAT에 함수 이름 정보가 남아 있지 않은 항목은 `<bound IAT>`로 표시합니다.
- 프로세스·이미지 알림 콜백과 이벤트 기능은 제거되었습니다. 스레드 종료도 제공하지 않습니다. 기존 ABI의 0x817 / 0x818은 비활성 호환 응답만 유지합니다.

PE 형식 해석은 [Microsoft PE 사양](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format)에 따라 구현했습니다. PE 문자열·RVA·배열 크기·순환·깊이 상한을 확인합니다.

## 진단

### 복잡한 대상의 검색과 결과 한도

- New Scan은 기본적으로 자료형 크기에 맞춘 정렬을 사용합니다. 패킹된 구조체나 페이지 경계의 값을 검색하려면 **정렬 1바이트**를 선택하세요. 선택 범위의 시작 주소는 포함, 끝 주소는 제외합니다. 후보 상한은 1~50,000개입니다.
- 후보 상한 도달 또는 읽기 실패로 후보 집합이 불완전하면 `partial`과 안내문을 표시합니다. Next Scan으로 후보가 줄어도 이미 누락된 후보는 복구되지 않으므로 안내문을 유지합니다. 필요하면 범위를 좁혀 New Scan을 다시 시작하세요.
- 메모리 맵 화면은 기본 5,000개를 표시하며 최대 50,000개까지 요청할 수 있습니다. 전체 스캔·이미지 분석·덤프·맵 스냅샷은 내부에서 최대 50,000개 맵을 요청합니다. 이 한도를 초과하면 전체 맵이 필요한 작업은 명시적으로 거부합니다.
- 인코딩·암호화·분할된 논리 값은 일반적인 평문 숫자 검색으로 직접 찾을 수 없습니다. 일치 결과가 없다는 응답을 평문 저장이 없다는 증거로 해석하지 마세요.
- 스레드 목록은 64개, 핸들 목록은 128개가 기존 ABI의 상한입니다. 별도 조회한 전체 개수와 잘림 여부를 표시합니다. 전체 개수와 목록은 서로 다른 조회 시점의 값입니다.

### 편집·종료·이전 HTTP 경로

- 스레드 작업에 PID가 주어지면 해당 스레드의 소속과 종료 상태를 검사합니다. 레지스터 편집은 요청한 필드만 검증하며, 실행 중 자연스럽게 변할 수 있는 다른 필드의 차이를 별도로 보고합니다. 중첩 정지 횟수는 편집 전 상태로 복원합니다.
- 관리 중인 할당의 해제에는 저장 당시의 프로세스 시작 키를 검사합니다. 할당·목록 조회 시 종료 또는 PID 교체가 확정된 대상의 관리 기록을 제거합니다. 이는 이미 종료된 대상의 기록 정리이며, 교체된 프로세스의 메모리를 해제하지 않습니다. 일시적인 조회 실패에서는 기록을 보존합니다.
- 기존 `/api/memory/copy` 경로도 커널 복사를 수행합니다. 기존 레지스터 편집 경로는 현대 편집 경로와 동일한 부분 편집 검증을 사용합니다.
- 기존 HTTP 경로에서 잘못된 숫자 주소·Hex·자료형 범위 오류는 커널 요청 전에 HTTP 400과 구조화된 오류로 반환합니다. 정상 입력의 동작과 결과 형식은 유지합니다.
- 기존 중단점 조회 경로는 서버 소유 반환 버퍼 주소 대신 해제 완료된 해석 결과를 반환합니다. 기존 중단점 설정·삭제는 관리 목록과 동기화됩니다. 이 응답 형식 변경은 외부의 이전 클라이언트에서도 반영해야 합니다.
- 2.3 커널은 값·문자열·VAD 결과의 생성 상한을 65,536개로 제한합니다. 초과 시 `STATUS_QUOTA_EXCEEDED (0xC0000044)`로 실패하고 생성한 결과를 정리합니다. 대량 값을 자동으로 잘라 성공으로 반환하지 않습니다. 2.2 실전 검사에서 발견한 생성/해제 상한 불일치의 수정입니다.

2026-10-04 상용화 점검은 복잡한 C++ 대상에서 2회전의 실제 HTTP·IOCTL 시험, 실패 재현과 수정 후 재시험으로 수행했습니다. 2.3의 Release/Debug 빌드 및 함수 본문 경계 모델 시험은 통과했습니다. 로드된 2.2에서 확인한 실전 결과와 2.3 수동 재로드 후 필요한 실전 검증은 보고서에서 구분합니다. DOM 시뮬레이션은 실제 브라우저의 시각적 검사를 대신하지 않습니다.

`python test_driver_all_ioctl.py` 또는 `python test_driver_readonly.py`는 7개 읽기 전용 진단만 실행합니다. 이전의 무조건 성공 판정과 빈 컨텍스트 쓰기는 제거했습니다. 이 명령은 전체 IOCTL 실전 검사를 완료했다고 표시하지 않습니다. `python -m unittest test_stability_regressions test_extensions_regressions -v`는 모의 실패·정확도·소유권·PE 입력 경계 상황을 검사합니다. 이번 전체 실전 결과와 재현용 테스트 프로세스는 별도 검증 패키지에 포함했습니다.
