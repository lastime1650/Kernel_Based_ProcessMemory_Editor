# DLL·이미지 함수 작업 공간

`http://127.0.0.1:8000/`에서 프로세스를 선택하고 **DLL / 이미지 함수** 메뉴를 엽니다.

1. DLL 절대 경로를 입력하거나 DLL 파일을 선택한 뒤 **DLL 로드 요청**을 실행합니다. 커널의 기존 DLL 로드 IOCTL을 사용하며, 이후 대상의 MEM_IMAGE 목록에 나타난 이미지와 주소를 확인합니다. 로드가 지연되면 **로드 확인 갱신**으로 확인합니다.
2. **메모리 이미지 목록**에서 DLL 또는 EXE를 선택하고 **이미지 함수 분석**을 실행합니다. 기존 MEM_IMAGE 외에, MEM_COMMIT 상태이고 읽기 가능하며 Guard가 아닌 각 영역의 시작에서 MZ/PE 헤더를 검사합니다. 따라서 실행 권한이 없는 읽기 전용 4KB 헤더 페이지 및 MEM_PRIVATE/MEM_MAPPED의 비등록 PE도 목록에 포함됩니다. 발견 근거는 커널 이미지 정보와 PE 헤더로 구분합니다. 대상의 PE 헤더, Export, x64 unwind 함수 범위를 커널로 읽습니다. 이름이 없는 함수는 `sub_주소`로 표시됩니다. 전달 Export와 데이터 Export는 호출할 함수에서 제외됩니다.
3. 필요한 경우 PDB 파일을 추가하거나 서버의 PDB 경로를 입력한 뒤 다시 분석합니다. 메모리 이미지의 CodeView GUID와 Age가 모두 일치해야 적용됩니다. 비공개 함수 이름, 매개변수 이름·형식, 반환 형식을 DIA로 복원합니다. PDB 분석은 로컬 파일 분석이며 대상 프로세스를 열지 않습니다. 등록한 PDB는 서버 재시작 후에도 유지됩니다. 제거 시 사용자가 입력한 원본 PDB는 삭제하지 않습니다.
4. 함수의 **선택 / 상세**를 누르면 **어셈블리 / 흐름 그래프 / C 의사코드** 탭을 표시합니다. 함수 바이트는 기존 커널 메모리 읽기로 가져옵니다. 그래프는 기본 블록을 위에서 아래로 정렬하고 참·거짓·반복 경로를 색으로 구분합니다. 노드 클릭으로 전체 명령을 확인하며, 드래그 이동·휠 확대·화면 맞춤·SVG 저장을 지원합니다. 의사코드는 로컬 변수를 `v1`, `v2` 등으로 표시하며 변수 대응표, 복사, C 형태 저장을 지원합니다. PDB가 없을 때 표시하는 RCX/RDX/R8/R9 후보는 정적 추정이며 실제 개수나 형식의 보장이 아닙니다. PDB가 없는 leaf 함수는 목록에서 누락될 수 있습니다.
5. 드라이버 2.2 이상에서는 **커널로 함수 호출**을 실행할 수 있습니다. 함수 시작 주소와 **단일 64비트 정수/포인터 인자**를 전달합니다. 종료값은 32비트입니다. 16진수 인자는 `0xFEDCBA9876543210`처럼 입력하며 문자열로 전달하여 정밀도를 유지합니다. 인자가 가리키는 주소는 대상 프로세스의 주소여야 합니다. 함수가 다른 규약을 요구하면 DLL에 단일 인자를 받는 진입 함수를 작성해야 합니다. PDB에서 확인된 다중 인자, 부동소수점, 멤버 함수, 64비트 반환 형식은 직접 호출을 차단합니다.
6. 호출 이력에서 TID, CallId, 실행 여부와 종료값을 확인합니다. 초기 대기 상한은 1초이며 이후 자동 조회합니다. **추적 해제**는 커널 기록의 참조를 해제합니다. 실행 중인 스레드를 종료하거나 DLL을 언로드하지 않습니다. 시간 초과 또는 통신 실패 시 호출을 자동 재전송하지 않습니다.

대상 접근 경로는 브라우저 → Python API → 드라이버입니다. 컨트롤러가 사용하는 대상 접근 API는 드라이버 장치를 여는 `CreateFileW`, `DeviceIoControl`, 장치 핸들을 닫는 `CloseHandle`입니다. `OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`, `CreateRemoteThread` 등으로 대상을 직접 조작하지 않습니다.

이미지 분석 직후에도 대상이 스스로 DLL을 언로드하거나 코드를 바꿀 수 있습니다. 호출 전에 PID 시작 키, 이미지 존재 여부와 헤더를 다시 확인하지만, 대상의 로더와 원자적으로 잠그는 기능은 아닙니다. 사용자가 호출할 수 있도록 설계한 함수의 진입점을 선택하세요.

### MEM_IMAGE 외의 PE 발견

**모듈 / PE / 주소 → 모듈 / 메모리 PE 목록**과 **DLL / 이미지 함수 → 메모리 이미지 목록**은 같은 발견 로직을 사용합니다. 단순한 MZ 문자열만으로 이미지로 판정하지 않습니다. PE 서명, 아키텍처, 선택 헤더, 정렬, SizeOfImage, 섹션 개수·범위를 검증합니다. Guard/예약/읽기 불가 영역은 읽지 않습니다. 영역 내부의 모든 바이트를 검색하는 방식이 아니라 각 메모리 영역의 시작을 검사합니다.

표의 이미지 크기는 **SizeOfImage**이며 실제 커밋된 바이트 수를 별도로 표시합니다. 4KB 헤더만 존재해도 유효한 헤더라면 이미지로 표시하지만, 이를 전체 실행 코드가 존재하거나 Windows 로더에 등록된 증거로 취급하지 않습니다. 일부 영역이 사라지거나 이름 정보가 읽히지 않아도 유효한 헤더 발견 결과는 유지합니다. 완전한 함수 분석에는 RVA 배치의 실제 코드·메타데이터가 필요합니다. 원시 파일 배치의 버퍼도 이름 조회 시 RVA→파일 오프셋을 적용하지만, 그것이 실행 가능한 로드 이미지로 변환되는 것은 아닙니다.

이름은 버전 정보의 OriginalFilename/InternalName, Export 디렉터리의 이미지 이름 순으로 확인합니다. PE 필수 헤더에는 파일명이 없을 수 있으며, 이름이 없으면 Characteristics의 DLL 비트에 따라 unknown.exe 또는 unknown.dll로 표시합니다. 대상 파일 경로는 추측해 만들지 않습니다.

PE 헤더 읽기는 대상의 동일 할당 범위 안에서만 수행하며, 메타데이터 조회량·헤더 크기·반복 횟수에 상한을 둡니다. 읽기 실패·헤더 제외 수는 discovery 응답에 포함됩니다. 프로세스가 교체되면 조회 결과를 반환하지 않습니다. 기존 드라이버 IOCTL만 사용하므로 이 변경에 드라이버 재빌드·재로드는 필요하지 않습니다.

상한: 이미지 함수 20,000개, PDB 분석 결과 50,000개, 등록 PDB 8개(각 256MB), 업로드 DLL 32개(각 64MB), 활성 호출 추적 30개, 호출 이력 128개, 이미지 분석 기록 16개. 상한 적용 여부는 응답에 표시합니다.

## 구현과 재빌드

### 그래프와 C 의사코드 분석 범위

Capstone으로 도달 가능한 직접 분기·조건 분기의 목적지와 이어지는 경로를 해석합니다. 첫 `ret` 또는 `jmp`에서 함수 전체 분석을 끝내지 않으며, 도달하지 않는 패딩은 제외합니다. 해석 경계가 겹치거나 간접 분기·범위 밖 분기이면 미해결 노드로 표시합니다. 점프 테이블의 간접 목적지를 추측하거나 대상 함수를 실행해 추적하지 않습니다.

정수 연산, 레지스터 일부 갱신, 메모리 읽기·쓰기, 스택, 조건 분기와 검증 가능한 반복문을 C 형태로 변환합니다. 복잡한 경로는 라벨과 `goto`로 보존합니다. 원본 C, 원본 지역 변수명·형식, 반환 형식, 호출 규약을 복원한다는 보장은 없습니다. `load/store/flags/call/unknown_*`는 동작을 표시하는 의사 연산이며, 결과가 그대로 컴파일되는 C 소스라는 의미가 아닙니다. 지원하지 않는 SIMD·특수 명령은 `asm_volatile`과 원문 목록으로 남깁니다. PDB 선언은 일치한 PDB의 형식 정보가 있을 때 별도로 표시하며 추정 선언과 섞지 않습니다.

알려진 함수 크기는 PDB/Unwind 정보에 따릅니다. 크기가 미확인되면 다음 식별 함수 또는 이미지 끝까지 최대 512바이트만 분석합니다. 알려진 함수도 최대 16KB·2,048개 명령·128개 기본 블록이며 상한과 미해결 경로를 표시합니다. 대상이 실행 중에 수정하는 코드는 순차 읽기의 특성상 한 시점으로 고정되지 않습니다. 새 드라이버 IOCTL이 필요하지 않습니다.

- `image_workbench.py`: 메모리 이미지 분석, PDB 대조, DLL 로드 검증, 호출 추적.
- `function_views.py`: 제공받은 메모리 바이트의 제어 흐름 해석과 보수적인 C 의사코드 변환. 자체 프로세스 접근은 없습니다.
- `static/function_views.js`, `static/function_views.css`: 탭, 그래프 정렬·이동·확대, 의사코드 표시·복사·저장.
- `memory_images.py`: MEM_IMAGE와 커밋 영역의 정상 PE 헤더 발견, 크기·파일 종류·이름 조회.
- `driver_bridge.py`: 0x822 생성 / 0x823 조회 / 0x824 참조 해제. 요청 크기 88/96/24바이트.
- `studio_api.py`: 9개 작업과 PDB/DLL 업로드 API.
- `static/dll_workspace.js`: DLL 작업 공간과 호출 이력.
- `native/pdb_symbols.cpp`: DIA PDB 분석 도구. 프로세스 PID를 입력받지 않습니다.

현재 환경의 Visual Studio 2022 Professional DIA SDK를 사용합니다. `native` 폴더에서 `build_pdb_symbols.cmd`로 도구를 빌드합니다. 다른 설치 경로에서는 빌드 파일과 `Symbols.dia` 경로를 조정해야 합니다. 추가 Python 패키지는 필요하지 않으며 기존 Capstone을 사용합니다.

새 기능 테스트: `python -m unittest test_image_workbench test_memory_images -v`. 실제 대상 테스트와 브라우저 모의 테스트는 함께 제공하는 보고서·테스트 패키지를 참고하세요.
