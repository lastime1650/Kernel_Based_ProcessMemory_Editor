# 디스어셈블리 작업 공간

왼쪽 **디스어셈블리** 메뉴에서 대상 프로세스의 주소를 입력하고 **주소 분석**을 누릅니다. 주소는 `0x` 형식 또는 10진수이며, 대상 메모리 읽기·페이지 보호 변경·쓰기는 기존 커널 드라이버 IOCTL로 처리합니다. 컨트롤 패널은 대상 프로세스를 OpenProcess로 열지 않습니다.

## 보기와 편집

- **어셈블리**: 주소, 원본 바이트, 명령어, 해석 가능한 참조 주소를 표시합니다.
- **흐름 그래프**: 기본 블록을 위에서 아래로 배치합니다. 노드 선택 시 블록의 전체 명령을 아래에도 표시합니다. 노드에서 축약된 줄도 전체 상세 목록에서 편집할 수 있습니다.
- **C 의사코드**: 기존 정적 분석기를 사용합니다. 변수는 `v1`, `v2` 등으로 표시하며 미변환 명령과 미해결 제어 이전을 숨기지 않습니다. 보기 전용이며 원본 C나 컴파일 가능한 코드 복원을 보장하지 않습니다.

ASM 또는 Graph의 명령어를 **더블클릭**하면 그 명령의 편집창이 열립니다. Intel 문법을 사용하며 대소문자를 구분하지 않습니다. 원본 주소·바이트·길이와 새 명령의 인코딩을 함께 보여줍니다. 잘못된 명령, 피연산자 오류, 길이 초과, 잘리는 즉시값·분기 주소는 빨간 사유로 표시하며 편집 대기 등록을 막습니다.

예를 들어 5바이트 `mov eax, 10`은 `MOV EAX, 100`으로 바꿀 수 있습니다. `xor eax, eax`처럼 짧은 명령은 뒤를 NOP으로 채웁니다. 원래 명령보다 긴 명령은 다음 명령을 덮어쓰므로 거부합니다. 여러 명령·지시문·라벨·주석 입력은 허용하지 않습니다.

**편집 대기 목록에 넣기**는 미리보기만 변경합니다. 원본→새 바이트를 확인하고 **편집 적용**을 눌러야 메모리에 기록합니다. 대기 편집이 남아 있으면 주소 이동을 막아 실수로 지워지지 않도록 합니다.

## 이동, 복원, 이력

**Ctrl+더블클릭**으로 명령의 참조 주소를 따라갑니다. 주소 칩은 해당 참조를 선택하고, 명령 자체에 여러 참조가 있으면 선택창을 엽니다. RIP/EIP 상대 주소와 절대 주소를 해석하며, 간접 `call [rip+...]`은 커널로 포인터를 읽어 실제 목적지로 이동합니다. 레지스터나 실행 중 계산에 의존하는 목적지는 확정하지 않습니다.

- **주소 Undo / Redo**: 주소 방문 이력의 뒤로 / 앞으로 이동입니다. 메모리를 수정하지 않습니다.
- **패치 Undo / Redo**: 적용한 편집 묶음의 복원 / 재적용입니다. 커널 쓰기 요청을 실행합니다.
- **대기 편집 지우기**: 아직 적용하지 않은 편집만 삭제합니다.
- **실패한 요청 복구**: 부분 쓰기 또는 페이지 보호 복구 실패 시 나타납니다. 외부 변경이 발견되면 덮어쓰지 않고 복구를 중단합니다.
- **이력 JSON 저장**: 적용 기록의 주소·명령·원본·적용 바이트를 저장합니다. 저장 파일을 가져와 자동으로 쓰는 기능은 없습니다.

같은 PID를 다시 선택해도 편집·주소 이력을 지웁니다. 재선택은 이미 적용된 메모리를 자동으로 복원하지 않습니다. 필요한 패치는 먼저 Undo로 복원해야 합니다. 서버 재시작·브라우저 재로딩 후 새 대상 선택은 새 작업 세션입니다. 대상 종료·PID 교체가 확인되면 기록과 분석을 폐기하고 재선택할 때까지 작업 버튼을 잠급니다. 작업 공간이 열려 있을 때 5초 간격으로 유효성을 확인합니다. 일시적인 장치 오류만으로는 복구 원본을 삭제하지 않습니다.

## 기록 처리

서버는 프로세스 생성 식별자와 분석 당시 명령 경계를 검사합니다. 모든 줄을 검증한 뒤 현재 바이트와 원본을 비교합니다. 커밋된 읽기 가능 영역만 편집하며 Guard·NoAccess를 제외합니다. 인접한 읽기 가능 영역을 넘어가는 명령도 분석합니다.

쓰기 불가능한 페이지는 커널로 잠시 쓰기를 허용하고, 실제 반환된 이전 보호 속성으로 복구합니다. 쓰기 결과의 길이를 검사하고 같은 커널 읽기 경로로 바이트를 다시 대조한 뒤 성공으로 기록합니다. 부분 실패 시 자동 원본 복구를 시도하고, 완료하지 못한 바이트·보호 복구 자료는 별도로 보관합니다. 외부 바이트 변경은 강제로 덮어쓰지 않습니다.

여러 바이트 패치는 실행 중인 대상 스레드와 원자적으로 동작하지 않습니다. 이 기능은 자동 스레드 중단이나 명령 캐시 플러시를 수행하지 않으므로, 대상이 해당 코드를 실행하지 않는 상태에서 적용해야 합니다. 코드 실행을 재개할 때 필요한 캐시 동기화는 별도의 대상 실행 제어 문제입니다.

## 범위와 한도

| 항목 | 한도 |
|---|---:|
| 아키텍처 | x86 / x64, 자동 감지 또는 수동 선택 |
| 한 번의 분석 | 1 ~ 16,384바이트 |
| 디코드 / 기본 블록 | 2,048개 / 128개 |
| 한 번의 편집 적용 | 1 ~ 128줄 |
| 한 대상 세션의 적용 이력 | 128회 |
| 주소 방문 이력 | 256개 |
| 서버 편집 세션 | 16개 |
| 세션의 분석 스냅샷 | 최근 8개 |

편집 이력 상한에서는 원본을 몰래 버리지 않고 새 적용을 거부합니다. 새 편집을 적용하면 이전에 Undo한 Redo 경로는 삭제됩니다. 명령 길이를 늘리는 트램펄린·코드 재배치 기능은 제공하지 않습니다.

## 구성

`disassembly_workspace.py`는 검증·패치·복원 API, `static/disassembly_workspace.js`는 작업 공간, `static/disassembly_workspace.css`는 편집 표시를 담당합니다. `function_views.js`의 선택적 콜백으로 공용 ASM·Graph에서 명령 편집과 참조 이동을 연결합니다. 기존 DLL / 이미지 함수 화면은 읽기 전용 동작을 유지합니다.

의존성은 Capstone 5와 `keystone-engine==0.9.2`입니다. [Keystone 공식 튜토리얼](https://github.com/keystone-engine/keystone-engine.github.io/blob/master/docs/tutorial.md)의 Intel 문법과 실제 시작 주소 인코딩을 사용합니다.

기존 커널 IOCTL의 입력·출력 및 드라이버 파일은 변경하지 않았습니다. 추가된 작업 이름은 `disasm_analyze`, `disasm_validate`, `disasm_apply`, `disasm_undo`, `disasm_redo`, `disasm_recover`, `disasm_history`, `disasm_follow`, `disasm_release`입니다.

분석 요청 예:

```json
{"operation":"disasm_analyze","args":{"pid":1234,"address":"0x140001000","size":1024,"bits":"auto"}}
```

반환된 `session_id`, `analysis_id`를 후속 검증·적용·참조 요청에 포함합니다. 적용 시 원시 바이트를 신뢰하지 않고 서버가 어셈블리를 다시 인코딩합니다.

```json
{"operation":"disasm_apply","args":{"pid":1234,"session_id":"...","analysis_id":"...","edits":[{"address":"0x140001000","text":"MOV EAX, 100"}]}}
```
