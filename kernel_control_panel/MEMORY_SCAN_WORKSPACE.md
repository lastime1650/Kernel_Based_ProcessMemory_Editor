# 메모리 스캔 작업 공간

브라우저의 **메모리 스캔**은 숫자, UTF-8/UTF-16LE 문자열, AOB, 여러 숫자 필드로 이루어진 구조체를 같은 화면에서 검색한다. Legacy NocturneMemory의 `studio.py`, `studio_v3.py`, `unknown_scan.py`, `scan_conditions.py`, `scan_buffers.py`에 있는 결과/보관 배치, 변경 강조, 표시 값과 검색 기준의 분리, 디스크 후보 유지 방식을 참고했다.

## 사용 흐름

1. 대상 프로세스를 선택한다.
2. 우측에서 형식, 조건, 값을 지정한다. 초기값을 모르면 숫자 또는 구조체의 Unknown을 사용한다.
3. **New**로 메모리 범위를 검색한다. 주소를 포함한 첫 페이지가 자동으로 표시된다.
4. 대상 값이 바뀐 뒤 **Next**를 실행한다. 증가/감소/변경/유지는 검색값 입력 없이 직전 검색 스냅샷과 비교한다.
5. **Rescan**은 기존 후보 주소를 유지하며 값을 다시 읽어 검색 기준을 갱신한다. 읽을 수 없는 후보는 제거되며 실패 개수가 표시된다.
6. 결과 체크박스로 여러 주소를 선택한 뒤 보관한다. 행 더블클릭으로도 보관한다. 주소 클릭은 Hex 보기로 이동한다.
7. 보관 목록의 값을 더블클릭하거나 편집 버튼으로 변경한다. 현재 표시 바이트와 쓰기 직전 바이트가 같은지 확인하고 커널로 쓴 뒤 다시 읽어 검증한다.

New와 검색 초기화는 보관 주소를 유지한다. 대상 재선택은 검색·보관·고정 상태를 해제한다. 페이지 새로 고침은 새 세션을 시작한다. 브라우저를 닫으면 세션 해제를 요청하며, 요청이 유실되면 서버가 마지막 접근 30분 후 만료시킨다.

## 조건과 데이터

| 형식 | 조건 |
|---|---|
| signed/unsigned 8/16/32/64비트, Float, Double | Exact, Unknown, 증가, 감소, 변경, 유지, 불일치, 초과, 미만, 이상, 이하, 범위 |
| UTF-8 / UTF-16LE / AOB | Exact, 불일치, 변경, 유지, Rescan |
| 구조체 | Exact(필드 조건의 AND), Unknown, 증가, 감소, 변경, 유지, Rescan |

숫자의 Exact 비교값은 해당 저장 형식으로 변환한다. Float32는 입력을 Float32로 반올림한 후 비교한다. 변경/유지는 원시 바이트를 비교하므로 NaN의 비트 패턴과 +0/-0도 구별한다. 64비트 숫자는 응답/화면에서 문자열로 유지한다.

문자열은 입력한 UTF 바이트열이 놓인 시작 주소를 찾는다. 대소문자를 구별하고 최대 256바이트를 검색한다. 문자열 검색은 문자열 목록 추출과 구별된다. AOB는 `DE AD ?? A? ?F`처럼 바이트/니블 와일드카드를 지원하며 모두 와일드카드인 입력은 거절한다.

구조체는 최대 32개 숫자 필드, 최대 1024바이트이다. 각 필드의 이름, offset, 형식, Exact/불일치/대소/범위/무시 조건을 편집한다. 증가/감소는 무시하지 않은 모든 필드가 해당 방향으로 변해야 한다. 변경/유지는 패딩을 포함한 구조체 전체 바이트를 비교한다. Unknown/상대 조건에는 필드 비교값이 필요 없다. 검색 결과를 기존 구조체 해석 화면으로 보낼 수도 있다.

Next에서는 최초 데이터 형식, 바이트 길이, 구조체 offset/형식을 유지한다. New로 새로운 배치를 시작할 수 있다. 주소 범위의 끝은 제외한다. 정렬은 절대 주소 기준이며 1바이트 정렬로 비정렬 값을 포함할 수 있다.

## 대량 후보와 실시간 표시

- 후보 개수에 따른 50,000개 중단이 없다. 전체 스냅샷과 압축 후보 마스크를 SQLite에 저장한다.
- 검색 예산은 기본 256MiB, 화면에서 16MiB~4GiB를 선택한다. 검색 영역 합계, 읽은 바이트, 실패, 예산 초과를 표시한다. 예산으로 잘린 검색은 전체 검색으로 표시하지 않는다.
- 페이지는 50/100/200/500개이다. 후보는 페이지 밖에서도 Next에 포함된다. 페이지 이동은 작은 주소/개수 인덱스를 사용해 건너뛴 페이지의 스냅샷을 읽지 않는다.
- 커널 읽기 실패는 4KiB 단위로 분리한다. 누락 바이트를 0으로 채워 후보를 생성하지 않는다. 연속 범위와 청크 경계에서 문자열/AOB/비정렬 값이 잘리지 않게 이어 읽는다.
- New/Next는 트랜잭션으로 처리한다. 취소·디스크 부족·치명적 복사 버퍼 실패 시 직전 검색과 기준값을 보존한다.
- 표시 페이지와 보관 목록을 250/500/800/1000/2000ms 간격으로 읽는다. 화면이 숨겨졌거나 검색 중이면 표시 갱신을 쉬며 요청을 겹치지 않는다.
- **현재값**은 실시간 읽기, **검색 기준값**은 직전 완료된 검색, **이전 기준값**은 그 이전 검색이다. 표시 갱신은 Next의 비교 기준을 바꾸지 않는다.
- 변경은 색으로 강조한다. 선택과 정렬은 갱신으로 이동하지 않는다. 명시적인 정렬 버튼 클릭 시 다시 정렬한다.
- 결과 필터와 CSV는 현재 표시 페이지에 적용한다. 전체 후보를 삭제/제한하지 않는다.

## 보관·편집·고정

세션당 최대 256개 보관 주소를 지원한다. 숫자, 고정 길이 문자열, AOB 원시 바이트, 구조체 원시 바이트를 편집한다. 기존 길이를 유지하고 전체 쓰기 크기는 최대 1024바이트이다. 구조체는 offset/형식/이름도 저장해 다른 검색 형식으로 변경한 후에도 보관 해석이 유지된다.

숫자 고정은 100ms 간격으로 커널 쓰기를 반복한다. 검색 중에는 해당 세션의 고정이 일시 정지한다. 해제/삭제/세션 종료 응답은 이미 시작한 쓰기가 끝난 후 반환한다. 대상 종료·PID 재사용·쓰기 실패 시 고정을 끈다. JSON 주소 목록 불러오기는 현재 PID/프로세스 시작 신원이 같은 파일만 허용하고 고정을 자동 실행하지 않는다.

대상 신원은 커널의 process_start_key로 확인한다. 종료/교체/만료/복사 버퍼 처리 실패 시 현재값 표시와 편집/주소 이동을 중지하고 다시 선택하도록 표시한다. 실행 중인 대상의 메모리는 각 읽기 시점 사이에도 바뀔 수 있다. 프로세스를 정지시키는 원자 스냅샷은 제공하지 않는다.

## 전송과 API

커널 신원 조회 0x800, VAD 0x807, 읽기 0x805, 반환 버퍼 해제 0x802/0x808, 쓰기 0x80F를 사용한다. 대상 프로세스 핸들을 열지 않는다. 반환된 로컬 복사 버퍼는 커널 요청으로 해제한다. NumPy는 복사된 바이트 비교만 수행한다.

| API | 동작 |
|---|---|
| POST `/api/studio/scans` | PID와 시작 신원을 묶은 세션 생성 |
| POST `/api/studio/scans/{id}/new` | 비동기 첫 검색 |
| POST `/api/studio/scans/{id}/next` | 비동기 후보 재검사/좁히기 |
| POST `/api/studio/scans/{id}/rescan` | 후보 기준 갱신 |
| POST `/api/studio/scans/{id}/results` | 페이지와 실시간 보관 값 반환 |
| POST `/api/studio/scans/{id}/save` | 보관 추가 |
| POST `/api/studio/scans/{id}/edit` | 값/설명/고정/삭제 |
| POST `/api/studio/scans/{id}/reset` | 검색만 초기화 |
| GET `/api/studio/scan-jobs/{id}` | 진행률/부분 결과 통계/완료 상태 |
| POST `/api/studio/scan-jobs/{id}/cancel` | 다음 체크포인트부터 취소 |
| DELETE `/api/studio/scans/{id}` | 고정 중지/임시 DB 제거 |

동시 세션 4개, 검색 worker 2개, 완료 포함 작업 이력 32개이다. 각 세션은 검색 하나만 실행한다. 기존 `/api/scan/*` 및 Studio 검색 API는 호환성을 위해 유지한다. 새 화면은 이 문서의 세션 API를 사용한다.

회귀 검사는 `python -m unittest test_scan_workspace` 및 전체 `python -m unittest discover -p 'test*.py'`로 실행한다.
